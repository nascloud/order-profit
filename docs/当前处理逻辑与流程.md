# 当前处理逻辑与流程

本文档说明当前版本订单利润核算程序的实际处理流程。金额计算以整数“分”为内部权威口径，Excel 和 HTML 只负责展示同一份聚合结果。

## 1. 输入文件

程序按运行参数读取以下文件：

| 文件 | 用途 | 是否必需 |
|---|---|---|
| 订单表 | 订单明细、状态、付款时间、商品 ID、商家编码、退款、备注、物流单号 | 必需 |
| 成本编码表 | 按商家编码匹配产品名称、单件成本、标准运费 | 可选，完整核算通常需要 |
| 运费表 | 按物流单号匹配实际运费 | 可选 |
| 售后表 | 按退款完结日期做主订单级退款复核 | 可选 |
| 推广报表 | 按日期和商品链接汇总推广花费、归因成交、展现点击 | 可选 |
| 人工补充表 | 补齐成本编码表或运费表无法解析的成本、运费 | 可选 |

读取后会统一处理：

- 文件 SHA-256、源文件、工作表、源行号审计字段。
- 主订单编号、商品 ID、物流单号、退款编号、推广主体 ID 等 ID 字段。
- 商家编码。
- 日期、数量、金额字段。
- 输入字段、重复字段、编码冲突、非法金额和非法日期。

## 2. 总流程

```text
读取输入
-> 标准化 ID / 日期 / 金额
-> 应用人工补充
-> 订单清洗与分区
-> 解析成本和运费
-> 计算订单利润
-> 售后退款复核
-> 推广汇总
-> 店铺 / 每日 / 产品 / 链接 / SKU 聚合
-> SABC 分级
-> 勾稽校验
-> 输出 Excel / HTML / manifest / 待补表
```

正式 `run` 命令会先写入临时目录，所有文件生成并校验通过后，再原子替换目标输出目录。失败时不覆盖上一份成功报告。

## 3. 订单清洗与分区

### 3.1 刷单标记

商家备注命中独立的 `D/d` 或 `S/s` 时，订单标记为刷单，但不再删除。

独立字母的判断会避开与英文或数字相邻的内容，避免误判物流单号或普通英文备注。

刷单识别先于正常订单的商家编码缺失分流。命中标记的正常订单即使商家编码为空，也进入利润核算；货品成本和运费按刷单规则计为 0，不进入待补成本运费表。

刷单订单后续仍参与：

- 已付款销售额。
- 平台扣点。
- 综合税赋。
- 刷单金额展示。
- 刷单成本扣回。

刷单订单不再把货品成本、运费重复计入利润。

### 3.2 付款关闭订单

交易关闭订单先判断是否实际付款：

| 情况 | 处理 |
|---|---|
| 有付款时间且买家应付货款 > 0 | 付款后关闭，进入经营口径 |
| 无付款时间且无付款金额 | 未付款关闭，不进入经营指标 |
| 付款时间和付款金额矛盾 | 付款状态异常，阻止正式结论 |

付款后关闭再按物流单号分为：

| 分类 | 处理 |
|---|---|
| 付款后关闭且有物流 | 进入关闭已发货，计算关闭损失 |
| 付款后关闭且无物流 | 计入销售和退款，成本、运费、关闭损失为 0 |

### 3.3 日期过滤

进入经营口径的订单按订单付款时间过滤：

```text
开始日期 00:00:00 <= 订单付款时间 < 结束日期后一天 00:00:00
```

未付款关闭订单不要求付款时间。其他未命中清洗删除规则的订单如果付款时间为空，会阻止运行。

### 3.4 经营分区

过滤后订单进入互斥分区：

| 分区 | 含义 |
|---|---|
| 正常订单 | 买家已付款待发货、卖家已发货待确认、交易成功 |
| 关闭已发货 | 付款后关闭且有物流 |
| 关闭未发货 | 付款后关闭且无物流 |
| 未付款关闭 | 不进入经营指标 |
| 付款异常 | 关闭订单付款时间和金额矛盾 |
| 无商家编码 | 有效状态但商家编码为空、未命中正常订单刷单规则且未通过人工补充补齐成本运费 |
| 其他状态 | 不属于当前经营口径 |
| 超出日期范围 | 付款时间不在本次期间 |

程序会校验源订单行在这些分区中守恒，不能重复或丢失。

## 4. 人工补充

人工补充先在全量标准化订单上匹配，再进入订单分区。

基础匹配键：

```text
主订单编号 + 商品ID + 商家编码
```

如果基础键匹配多条订单明细，使用 `明细序号` 精确定位原订单行。

生效状态：

- 空值
- 已确认
- 已同步

草稿、作废不参与核算。其他状态为非法输入。

人工补充金额是订单明细总金额，不再乘购买数量。

## 5. 成本和运费解析

### 5.1 货品成本

解析优先级：

1. `补差价专用`：成本为 0。
2. 成本编码表：`单件成本 × 购买数量`。
3. 人工补充：直接使用补充的明细总成本。
4. 仍无法解析：成本缺失。

命中刷单标记的正常订单，货品成本按刷单业务规则计为 0。

### 5.2 运费

解析优先级：

1. 运费表按物流单号匹配实际运费。
2. 多明细共用同一运单时，按购买数量分摊，整数分尾差按确定性规则分配。
3. 成本编码表标准运费。
4. 人工补充明细总运费。
5. `补差价专用`：无实际运费时运费为 0。
6. 仍无法解析：运费缺失。

命中刷单标记的正常订单，运费按刷单业务规则计为 0。

付款后关闭且无物流的订单，成本和运费按业务规则为 0。

## 6. 利润计算

### 6.1 正常订单

每条正常订单明细计算：

```text
实收金额 = 买家应付货款
有效退款 = 退款状态为“退款成功”时的退款金额，否则为 0
费用计费基数 = MAX(实收金额 - 有效退款, 0)
平台扣点 = 费用计费基数 × 平台扣点率
综合税赋 = 费用计费基数 × 2.3%
```

平台扣点率：

| 平台 | 扣点率 |
|---|---:|
| 天猫 tmall | 6% |
| 淘宝 taobao | 0.6% |

非刷单正常订单利润：

```text
正常订单利润
= 实收金额
- 有效退款
- 货品成本
- 运费
- 平台扣点
- 综合税赋
```

刷单正常订单利润：

```text
刷单成本 = 实收金额

正常订单利润
= 实收金额
- 有效退款
- 刷单成本
- 平台扣点
- 综合税赋
```

刷单订单不再扣货品成本和运费，避免重复扣减。

### 6.2 关闭已发货

付款后关闭且有物流的明细：

```text
关闭已发货损失 = 货品成本 + 运费
关闭明细利润 = 实收金额 - 有效退款 - 平台扣点 - 综合税赋 - 关闭已发货损失
```

关闭已发货损失在报表中以正数展示。

### 6.3 关闭未发货

付款后关闭且无物流的明细：

```text
关闭已发货损失 = 0
关闭明细利润 = 实收金额 - 有效退款 - 平台扣点 - 综合税赋
```

## 7. 销售和退款口径

```text
净销售额 = 已付款销售额 - 订单批次成功退款金额
真实销售额 = 已付款销售额 - 订单批次成功退款金额 - 刷单金额
```

退款分两套口径：

| 口径 | 来源 | 日期归属 | 用途 |
|---|---|---|---|
| 订单批次成功退款 | 订单表退款状态和退款金额 | 原订单付款日期 | 订单、每日、产品、链接和利润核算 |
| 期间退款完结金额 | 售后表退款完结时间 | 退款完结日期 | 财务现金流复核 |

两者不相加，也不互相覆盖。

售后表只做主订单级复核，不直接修改利润结果。

## 8. 推广处理

推广数据按推广日期过滤到本次期间。

推广明细按主体 ID 聚合到商品链接维度，并按日期生成每日推广汇总。

核心指标：

```text
推广花费 = SUM(花费)
推广归因成交金额 = SUM(总成交金额)
推广投产比 = 推广归因成交金额 / 推广花费
平均点击花费 = 推广花费 / 点击量
点击率 = 点击量 / 展现量
```

推广花费从经营贡献利润中扣除。推广归因成交金额只用于投产分析，不重复计入订单销售额。

## 9. 聚合报表

程序生成同一份内存聚合结果，再分别写入 Excel、HTML 和 manifest。

### 9.1 店铺总览

汇总全部有效订单和推广数据，展示：

- 已付款销售额。
- 订单批次成功退款金额。
- 期间退款完结金额。
- 刷单金额。
- 真实销售额。
- 已核算销售额。
- 货品成本、运费、刷单成本。
- 平台扣点、综合税赋。
- 关闭已发货损失。
- 推广花费。
- 含推广经营贡献利润。
- S/A/B/C/待核算链接数量。

店铺利润链：

```text
含推广经营贡献利润
= 已核算销售额
- 已核算订单批次成功退款
- 已核算货品成本
- 已核算运费
- 已核算刷单成本
- 已核算平台扣点
- 已核算综合税赋
- 关闭已发货损失
- 推广花费
```

### 9.2 每日经营

每天按订单付款日期、售后退款完结日期、推广日期合并展示。

即使当天没有订单或推广，也保留日期行。

### 9.3 产品分析

产品名称来自成本编码表。产品维度按订单明细拆分。

多产品链接的推广花费、推广归因成交金额和推广成交笔数，按该链接内各产品已付款销售额占比分摊，分摊金额按整数分守恒。

### 9.4 链接分析

链接维度使用：

```text
订单表.商品ID = 推广表.主体ID
```

链接集合包含：

- 至少有一条有效订单的商品 ID。
- 或至少有一条期间内推广数据的主体 ID。

链接展示订单、退款、成本、运费、刷单、平台费用、税赋、关闭损失、推广和经营贡献利润。

## 10. SABC 分级

SABC 按商品链接分级，使用链接的含推广经营贡献利润，不按销售额分级。

| 等级 | 规则 |
|---|---|
| 待核算 | 成本或运费缺失 |
| C | 已核算且含推广经营贡献利润 <= 0 |
| S | 正利润链接中，分级前累计盈利贡献率 < S 阈值 |
| A | 正利润链接中，分级前累计盈利贡献率 >= S 阈值且 < A 阈值 |
| B | 正利润链接中，分级前累计盈利贡献率 >= A 阈值 |

默认阈值：

```text
S = 50%
A = 80%
```

可以通过 `--sabc-config` 指定 JSON 配置：

```json
{
  "s_profit_share": 0.50,
  "a_profit_share": 0.80
}
```

完整规则见：[SABC分级规则说明.md](SABC分级规则说明.md)。

## 11. 交付状态

| 状态 | 含义 |
|---|---|
| FINAL | 成本运费完整，勾稽通过，可正式使用 |
| PROVISIONAL | 流水线和勾稽通过，但仍有成本/运费缺失、无商家编码或付款异常 |
| FAILED | 输入、核算、勾稽或输出失败 |

`PROVISIONAL` 时会生成 `待补成本运费.xlsx`。如果启用 `--require-complete`，存在缺失会直接阻止交付。

## 12. 输出文件

正式运行输出：

| 文件 | 内容 |
|---|---|
| `订单成本利润分析.xlsx` | Excel 管理报表和核算底稿 |
| `店铺经营复盘.html` | 离线 HTML 经营复盘 |
| `manifest.json` | 输入、配置、状态、汇总、勾稽和 SABC 配置快照 |
| `待补成本运费.xlsx` | 仅 PROVISIONAL 时生成，供人工补齐 |

## 13. 勾稽校验

输出前会校验：

- 订单分区源行守恒。
- 店铺、每日、产品、链接金额和数量口径一致。
- 推广花费在明细、每日、链接、产品分摊中守恒。
- S/A/B 正利润合计和 C 类亏损口径分开。
- Excel、HTML、manifest 来自同一份聚合结果。
- 输出文件完整且 manifest 是合法 JSON。

勾稽失败时，运行状态为 `FAILED`，不会发布正式报告。
