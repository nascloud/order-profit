# 经营报表升级实施计划

## 1. 目标

在保留现有“整数分核算、逐明细舍入、缺失成本不填零、推广归因成交金额不重复计入销售额”等基础规则的前提下，将最终报表升级为老板、财务、运营可以共同使用的经营分析报表。

本次明确包含两项业务口径变更：

- 付款后关闭订单纳入已付款销售和订单批次退款分析。
- 现有“含推广净利润”统一更名为“含推广经营贡献利润”。该指标尚未包含人工、仓储、包装、退货入库、其他平台费用和期间费用，不得作为会计净利润使用。

固定平台扣点和综合税赋是管理估算值。报表必须展示实际采用的费率；只有未来接入平台结算明细后，才可将其标记为实际结算费用。

最终继续输出：

- `订单成本利润分析.xlsx`：管理报表与财务核算底稿。
- `店铺经营复盘.html`：适合老板和运营查看的离线交互报表。
- `manifest.json`：运行状态、输入审计和勾稽结果。
- `待补成本运费.xlsx`：仅在 `PROVISIONAL` 状态下生成。

Excel 和 HTML 必须共用 `PipelineResult` 中的同一份聚合结果，禁止分别计算造成口径不一致。

## 2. 使用对象

| 使用人 | 主要关注内容 |
|---|---|
| 老板 | 销售额、经营贡献利润、经营贡献利润率、趋势、核心产品、核心链接、主要风险 |
| 财务 | 收入与退款、成本费用拆解、关闭订单损失、数据完整度、勾稽状态 |
| 运营 | 推广花费与推广投产比、产品表现、链接 SABC 等级、亏损原因、行动建议 |

## 3. 报表结构

### 3.1 Excel 工作表顺序

新增并优先展示四张管理报表：

1. `01_经营总览`
2. `02_每日经营`
3. `03_产品分析`
4. `04_链接分析`

现有订单、售后、推广、清洗、补充和规则工作表继续保留在后面，作为财务底稿和审计依据。原有重复的汇总型工作表可在新报表覆盖其用途后删除，避免同一指标出现多个版本。

### 3.2 HTML 页面结构

HTML 使用四个视图：

1. 经营总览
2. 每日经营
3. 产品分析
4. 链接分析

继续生成单文件、自包含、离线可打开的 HTML，不增加 Web 服务或前端框架。

## 4. 统一指标口径

### 4.1 店铺整体

经营总览至少包含：

- 已付款销售额
- 订单批次成功退款金额
- 期间退款完结金额
- 净销售额
- 已核算销售额
- 已核算订单批次成功退款金额
- 已核算净销售额
- 已核算货品成本
- 已核算运费
- 平台扣点
- 综合税赋
- 关闭已发货损失
- 推广花费
- 推广归因成交金额
- 推广投产比
- 推广前经营利润
- 含推广经营贡献利润
- 含推广经营贡献利润率
- 销售额核算覆盖率
- 明细行核算覆盖率
- 待补成本运费行数
- S/A/B/C/待核算链接数量
- 盈利链接数和亏损链接数

经营总览使用图形公式链展示，不再用重复指标卡或费用表拆散计算关系：

```text
净销售额 = 已付款销售额 - 全部订单批次成功退款
已核算净销售额 = 已核算销售额 - 已核算订单批次成功退款
经营贡献利润 = 已核算净销售额 - 货品成本 - 运费 - 平台扣点 - 综合税赋 - 关闭已发货损失 - 推广花费
```

全部订单与已核算订单必须分别成链，核算结果放在公式左侧，退款名称必须标明统计范围；销售额核算覆盖率显示在已核算利润链标题旁。每个金额节点必须显示对应比例并写明分母口径；窄屏按公式顺序纵向排列，金额和运算符不得错位。

统一公式：

```text
净销售额 = 已付款销售额 - 订单批次成功退款金额
销售额核算覆盖率 = 已核算销售额 / 全部符合经营范围的已付款销售额
明细行核算覆盖率 = 已核算经营明细行数 / 全部应核算经营明细行数
含推广经营贡献利润
= 已核算销售额
- 已核算订单批次成功退款
- 已核算货品成本
- 已核算运费
- 已核算平台扣点
- 已核算综合税赋
- 已核算关闭已发货损失
- 推广花费
```

店铺、每日、产品和链接维度的成本率、运费率、平台费率、税费率、推广费率和经营贡献利润率统一使用对应范围的已核算净销售额作为分母；订单明细利润率使用该明细实收金额减有效退款后的净销售额作为分母。退款率使用全部符合经营范围的已付款销售额作为分母，销售额核算覆盖率仍使用已付款销售额作为分母。分母为零时显示“暂无比例”，不得显示可能造成误解的 `0.00%`。

`PROVISIONAL` 状态下必须显示“已核算部分经营贡献利润”，不得显示为完整店铺利润。完整链接可以生成“暂算 SABC”供运营排查，但不得作为正式 SABC 经营结论。

### 4.2 每日经营

按订单付款日期、售后退款完结日期与推广日期合并，覆盖所选期间内的每一个自然日，即使当天没有订单、退款或推广也保留一行。

字段至少包含：

- 日期
- 已付款主订单数
- 购买数量
- 销售额
- 订单批次成功退款金额和退款率
- 期间退款完结金额
- 净销售额
- 货品成本和成本率
- 运费和运费率
- 平台扣点和平台费率
- 综合税赋和税费率
- 关闭已发货损失
- 推广花费和推广费率
- 推广归因成交金额和推广投产比
- 推广前经营利润
- 含推广经营贡献利润和经营贡献利润率
- 当日销售额占期间销售额比例
- 累计销售额和累计经营贡献利润
- 核算覆盖率

每日退款必须分开归属：

- 订单批次成功退款按原订单付款日期展示，用于分析该批订单及商品质量。
- 期间退款完结金额按售后表退款完结日期展示，用于财务现金流复核。
- 两者不得相加，也不得互相覆盖；报表必须标明日期口径。

### 4.3 产品分析

产品名称来自成本编码表的 `产品名称` 字段，通过商家编码映射到订单明细后聚合。

字段至少包含：

- 产品名称
- SKU 数
- 商品链接数
- 已付款主订单数
- 购买数量
- 销售额、净销售额、已核算销售额及店铺销售贡献率
- 订单批次成功退款金额和退款率
- 货品成本、运费、平台扣点、税赋、推广花费
- 推广归因成交金额和推广投产比
- 推广前经营利润
- 含推广经营贡献利润、经营贡献利润率、利润率核算状态及店铺盈利贡献率
- 盈利链接数、亏损链接数
- S/A/B/C/待核算链接数量
- 成本运费缺失行数

产品归属规则：

- 成本表存在产品名称时按产品名称归集。
- 产品名称为空或商家编码无法匹配时归入“未归类”，不得根据商品标题猜测。
- 同一商家编码对应多个不同产品名称时，本次运行失败并提示修正成本表。
- 一个链接包含多个产品时，产品分析按订单明细拆分；链接分析中的产品名称显示“多产品”。
- 仅有推广、没有订单的链接无法取得成本表产品名称时归入“未归类”。

产品经营贡献利润率必须保证利润分子和收入分母属于同一完整产品范围：

```text
产品净销售额 = 产品已付款销售额 - 产品订单批次成功退款
产品经营贡献利润率 = 产品含推广经营贡献利润 / 产品净销售额
```

- 产品成本和运费完整且产品净销售额大于 0 时，才生成正式产品经营贡献利润率。
- 产品存在任何成本或运费缺失时，经营贡献利润率状态标记为“待核算”，利润率留空；不得用部分核算利润除以全部销售额或已核算销售额。
- 产品净销售额小于或等于 0 时显示“净销售额非正”，利润率留空，同时保留金额和异常供复核。
- 待核算产品可以展示“已核算部分经营贡献利润”金额，但不得生成正式利润率或店铺盈利贡献率。

产品维度的推广数据采用确定性管理分摊，不冒充平台实际归因：

1. 单产品链接的推广花费、归因成交金额和成交笔数全部归入该产品。
2. 多产品链接按各产品在该链接内的已付款销售额占比分摊推广花费和归因成交金额。
3. 分摊金额使用整数分并保证守恒；尾差按销售额从高到低、产品名称从小到大的顺序确定性分配。
4. 多产品链接没有已付款销售额时，推广数据全部归入“未归类”。
5. 产品报表必须显示“推广数据为链接级分摊估算”；产品推广投产比和经营贡献利润均基于该分摊值。

### 4.4 链接分析

字段至少包含：

- SABC 等级
- 产品名称
- 商品 ID、商品标题、商品链接
- 数据覆盖和核算状态
- 主订单数、购买数量
- 销售额及店铺销售贡献率
- 订单批次成功退款金额和退款率
- 货品成本、运费、平台扣点、综合税赋
- 关闭已发货损失
- 推广展现量、点击量、点击率、花费、归因成交金额、成交笔数、推广投产比
- 推广前经营利润
- 含推广经营贡献利润、经营贡献利润率和盈利贡献率
- 运营动作优先级和运营动作

HTML 支持按产品名称、SABC 等级、盈利状态、数据覆盖和核算状态筛选，并支持按销售额、经营贡献利润、经营贡献利润率、推广花费、推广投产比、退款率排序。

链接推广数据来自推广报表原始链接维度，不执行产品分摊。正利润链接显示“盈利贡献率”，分母为全部已核算正利润链接的经营贡献利润；C 类链接不显示盈利贡献率，改为显示其占全部亏损链接亏损额的“亏损占比”。

## 5. 链接 SABC 分级

分级使用完整核算后的“含推广经营贡献利润”，不使用销售额直接分级，避免将高销售但亏损的链接评为核心链接。

处理顺序：

1. 成本或运费不完整的链接标记为 `待核算`，不参与 SABC 排名。
2. 含推广经营贡献利润小于或等于零的链接标记为 `C`。
3. 其余盈利链接按含推广经营贡献利润从高到低排序；利润相同时按商品 ID 升序，保证结果稳定。
4. 计算每条链接占全部盈利链接利润的贡献率和累计贡献率。

默认等级：

| 等级 | 规则 | 经营含义 |
|---|---|---|
| S | 分级前累计贡献率低于 50%；首条正利润链接始终为 S | 核心利润链接，重点保障和放量 |
| A | 分级前累计贡献率达到 50%且低于 80% | 稳定盈利，继续优化增长 |
| B | 分级前累计贡献率达到 80%的其余正利润链接 | 有利润但贡献较低，控制投入 |
| C | 含推广经营贡献利润小于或等于 0 | 亏损或无贡献，优先整改 |
| 待核算 | 成本或运费不完整 | 先补数据，不做经营等级判断 |

SABC 与风险标签分别展示。风险标签继续使用确定性规则，包括：

- 补成本或运费
- 高退款
- 仅推广无订单
- 仅订单无推广
- 关闭已发货损失
- 推广后亏损
- 可加投观察

阈值边界采用“分级前累计贡献率”判断：

```text
分级前累计贡献率 < s_profit_share  -> S
分级前累计贡献率 < a_profit_share  -> A
其余正利润链接                       -> B
```

因此跨越阈值的链接归入前一等级，S 或 A 的最终累计占比允许因最后一条链接超过阈值。第一条正利润链接始终为 S。S/A/B 的经营贡献利润合计必须等于全部已核算正利润；C 类亏损单独汇总，不与盈利贡献率相加。

### 5.1 自定义 SABC 配置

采用可选 JSON 文件配置，不增加桌面 UI。命令行通过 `--sabc-config` 指定文件；未指定时使用 50%/80% 默认值。

```json
{
  "s_profit_share": 0.50,
  "a_profit_share": 0.80
}
```

配置含义：

- `s_profit_share`：进入 S 级时允许的分级前累计盈利贡献阈值。
- `a_profit_share`：进入 A 级时允许的分级前累计盈利贡献阈值；达到该值的其余盈利链接为 B 级。

校验规则：

```text
0 < s_profit_share < a_profit_share < 1
```

配置文件必须是 UTF-8 JSON，只允许上述两个字段。缺字段、未知字段、非数字、越界或顺序错误时直接阻止生成报表并给出明确错误，禁止静默回退默认值。

为防止错误配置把亏损链接评为核心链接，以下规则不可配置：

- 含推广经营贡献利润小于或等于零始终为 C。
- 成本或运费不完整始终为“待核算”。
- 利润最高的首条盈利链接至少为 S。

实际采用的阈值和配置文件路径写入 `manifest.json`、Excel“规则说明”和 HTML 报表页脚，保证报表可追溯。桌面 UI 暂不提供配置入口，桌面运行使用默认阈值。

## 6. 关闭订单与退款统计

### 6.1 付款后关闭的判断

订单必须先判断是否付款，再执行付款日期过滤。只有同时满足以下条件的关闭订单才进入经营和订单批次退款统计：

```text
订单状态 = 交易关闭
且订单付款时间不为空
且买家应付货款 > 0
```

订单付款时间是是否付款的主要依据，金额用于一致性校验。付款时间与金额互相矛盾时标记为“数据异常待核对”，该行留在审计明细并阻止正式 `FINAL` 交付，不自动猜测。

未付款关闭订单在日期过滤前进入独立审计分区，不要求付款时间，不进入经营指标。这样停止删除关闭无物流订单后，不会因未付款关闭订单缺少付款时间而导致整次运行失败。

### 6.2 分类处理

| 分类 | 经营报表处理 |
|---|---|
| 付款后关闭且无物流 | 纳入已付款销售和订单批次退款；货品成本、运费和关闭损失均为业务明确的 0，不属于待补数据 |
| 付款后关闭且有物流 | 纳入已付款销售和订单批次退款；同时计算货品成本与运费形成的关闭已发货损失 |
| 未付款关闭 | 不进入销售、退款、关闭率、产品或链接经营指标，仅保留在审计明细 |

样本核对结果：127 条关闭明细中，79 条有付款时间且应付金额大于 0，其中 11 条有物流、68 条无物流；另外 48 条无付款时间，不进入经营统计。

付款后关闭订单仍按订单明细逐行计算：

```text
订单批次成功退款 = 退款状态为“退款成功”时的退款金额，否则为 0
净销售额 = 买家应付货款 - 订单批次成功退款
平台费与税赋基数 = MAX(买家应付货款 - 订单批次成功退款, 0)
```

退款金额大于买家应付货款时不截断退款金额，净销售额允许为负，平台费与税赋基数保持为 0，并输出高优先级异常。

### 6.3 退款双口径

- 订单批次退款率 = 订单批次成功退款金额 / 已付款销售额
- 退款订单率 = 发生成功退款的已付款主订单数 / 已付款主订单数
- 付款后关闭率 = 付款后关闭主订单数 / 全部已付款主订单数
- 关闭已发货率 = 付款后关闭且有物流主订单数 / 全部已付款主订单数

订单批次退款优先使用订单表中状态为“退款成功”的退款金额，归属于原订单付款日期，用于订单、产品、链接和经营贡献利润。售后表按退款完结期间形成独立的“期间退款完结金额”，归属于退款完结日期，用于财务现金流复核。

售后表继续执行主订单级关联检查，但不得直接拿“期间退款完结金额”与“期间付款订单的订单批次退款”做等额强制勾稽。检查结果拆为：已匹配同一订单且金额一致、已匹配但金额不一致、售后属于非本期付款订单、订单退款未出现在本期售后四类。任何一类都不静默覆盖利润结果。

## 7. HTML 数字下方的百分比

主要金额和数量下方增加一行小字，必须同时显示比例名称，禁止只显示裸百分比。

示例：

```text
¥128,560.00
占店铺销售 18.42%

¥16,820.00
经营贡献利润率 13.08%
```

各视图对应关系：

| 视图 | 小字百分比 |
|---|---|
| 店铺总览 | 核算覆盖率、退款率、成本率、运费率、平台费率、税费率、推广费率、经营贡献利润率 |
| 每日经营 | 占期间销售、退款率、各费用率、当日经营贡献利润率 |
| 产品分析 | 占店铺销售、占店铺盈利、退款率、成本率、推广费率、经营贡献利润率 |
| 链接分析 | 占产品或店铺销售、盈利贡献率或亏损占比、退款率、推广费率、经营贡献利润率 |

显示规则：

- 正常比例使用次要文字颜色。
- 负利润和负贡献使用红色。
- 高退款或异常费用率使用警示色。
- 分母为零时显示“暂无比例”。
- 推广投产比保持倍数显示，例如 `2.35x`，不强行转换为百分比。

## 11. 验收标准

### 11.1 数据口径

- 店铺金额和购买数量等于每日汇总合计。
- 店铺金额和购买数量等于产品汇总合计，未归类产品也必须计入。
- 店铺金额和购买数量等于链接汇总合计，推广归因成交金额不得重复计入销售额。
- 店铺、产品和链接去重主订单数按主订单集合关系校验，不要求各行去重数直接相加。
- 付款后关闭订单进入退款分析；未付款关闭订单不进入任何经营指标。
- 有物流的付款后关闭订单计入关闭发货损失；无物流的不计发货损失。
- 付款后关闭且无物流的成本和运费为业务明确的 0，不得标记为成本运费缺失。
- 订单批次退款与期间退款完结金额按各自日期和范围汇总，不做错误的等额强制勾稽。
- 退款订单率、付款后关闭率和关闭已发货率必须按去重主订单数计算并在经营总览展示。
- 多产品链接的产品推广分摊金额逐链接、逐期间与原推广金额按分完全一致。
- S/A/B 经营贡献利润合计为全部已核算正利润链接利润，C 类亏损单独汇总。
- 成本或运费不完整的链接不得进入 SABC，必须显示为“待核算”。
- 待核算链接不得计入盈利链接数或亏损链接数。
- 完整产品的经营贡献利润率等于完整产品经营贡献利润除以产品净销售额；待核算产品和净销售额非正产品不得生成该比例。
- 全局状态为 `PROVISIONAL` 时，完整链接的等级必须标记为“暂算 SABC”，不得作为正式经营结论。
- 未提供 SABC 配置时使用 50%/80% 默认阈值；提供合法配置时按自定义阈值分级。
- 非法 SABC 配置（包括未知字段、缺字段、非数字、`NaN`、无穷值、越界或阈值顺序错误）必须以明确的配置错误阻止报表生成，不能静默使用默认值或抛出未处理异常。
- 报表和运行清单必须显示实际采用的 SABC 阈值。

### 11.2 输出一致性

- Excel、HTML 和内存聚合结果中的销售、两类退款、成本、费用、推广花费及经营贡献利润完全一致。
- HTML 每个主要数字的小字百分比与对应聚合字段一致。
- 分母为零时不出现除零错误或误导性的百分比。
- 产品名称、商品标题和其他业务文本正确转义，不产生公式注入或 HTML 注入。
- Excel 写后读回校验通过，不包含公式错误标记。
- `PROVISIONAL` 报表只能显示“已核算部分经营贡献利润”，不得显示为完整净利润。
- 报表必须显示固定平台费率、综合税赋率及“管理估算值”说明。

### 11.3 最小测试集

使用一个覆盖以下情况的小型固定样本：

- 正常盈利订单
- 正常退款订单
- 付款后关闭且无物流
- 付款后关闭且有物流
- 未付款关闭
- 付款时间与付款金额矛盾
- 退款金额大于付款金额
- 本期付款但跨期退款
- 本期退款但订单在前期付款
- 成本或运费缺失
- 一个产品包含多个 SKU
- 一个链接包含多个产品
- 多产品链接推广费分摊及整数分尾差
- 仅订单链接
- 仅推广链接
- 盈利与亏损链接
- S/A/B/C/待核算各等级
- 默认、自定义和非法 SABC 配置

真实样本生成后，还需核对关闭明细数量、四级汇总勾稽、SABC 分布和 HTML 页面显示。
